# 鸿蒙手机投屏到 Mac

已在本机 Apple Silicon Mac、macOS 27.0.1 与 LMR-AL10 / 鸿蒙 7.0.0.111 上验证 USB 视频流采集、解码及投屏窗口显示。窗口已接收到 1276 × 2848 的画面。

## 使用

推荐直接双击桌面上的 `鸿蒙投屏.app`（Apple Silicon）或 `鸿蒙投屏-Intel.app`（Intel）。每次打包成功后，脚本会自动将完整 App 同步到桌面。

App 内置 Java 17 与 `hdc`，不依赖本机 DevEco Studio 或 Java 安装路径。启动时默认优先连接上一次记住的手机 Wi-Fi 地址，Wi-Fi 和 USB 同时可用时优先使用 Wi-Fi；无线不可用时也能使用有线连接，原来的无线地址会保留。在窗口里切换到另一台 Wi-Fi 手机并成功收到画面后，会自动更新记忆，下次启动优先连接该手机。连接地址、配置及启动日志保存在 `~/Library/Application Support/HarmonyCast/`。

以下 `.command` 入口仍可使用：

1. 用支持数据传输的 USB 线连接手机，开启并授权 USB 调试。
2. 双击 `启动鸿蒙投屏.command`（同样默认 Wi-Fi 优先；明确使用有线连接时可在终端传入 `--usb`）。
3. 只有一台设备时自动进入投屏；多台设备时在窗口中选择设备并点击「进入投屏」。

多台手机同时使用时，下拉列表会列出已连接设备及记忆的 Wi-Fi 地址，选择要投屏的那台即可。程序每 4 秒检查设备（投屏期间也会检查）；USB 手机接入后，会自动读取 WLAN 地址、准备无线调试，并把对应的 Wi-Fi 地址加入列表。拔线或重启 App 后，地址仍可选择；选择 Wi-Fi 地址时会尝试建立无线连接，成功投屏后更新下次启动的优先目标。同一台手机换 Wi-Fi 后再次插线，会更新它的地址。USB 与 Wi-Fi 地址的对应关系保存在配置目录的 `usb-wireless-devices.properties` 中；手机和 Mac 仍需处于可互通的局域网。

窗口采用左右布局：左侧完整用于手机画面，保留圆角，不添加外围黑框或阴影；右侧集中放置设备选择、连接状态和全部操作按钮。按钮按导航与按键、滑动手势、画面与窗口、截图与录屏、文字与控件、文件与工具分组；右侧可独立滚动，缩小窗口后仍能访问所有操作。手机画面与操作区之间有一个无边框的小尖角箭头，悬停时显示淡色背景，点击可整体收起或展开右侧菜单；收起后隐藏顶部标题栏与红黄绿按钮，窗口四角透明并保持圆角，保持手机画面的大小，窗口宽度贴合画面并去掉两侧留白，背景切换为黑色；展开箭头覆盖在画面右侧边缘，不额外占宽度。展开后恢复原来的窗口尺寸、标题栏和背景，横竖屏变化时收起窗口也会跟随画面比例调整。无标题栏的小窗口可按住 ⌘Command 拖动画面移动位置；在画面上右键可展开菜单、切换置顶、缩小窗口或关闭投屏。普通收起模式保持小窗口，不进入全屏。进入并退出关灯模式会保留菜单原来的展开或收起状态。

在手机画面上点击、拖动，或使用右侧的返回、音量和锁屏按钮。画面保持长宽比例，随窗口缩放；右侧「放大 / 还原」按钮可放大或还原窗口。「画面与窗口」分组首位的「窗口置顶」按钮可将投屏窗口保持在其他普通应用窗口上方，开启后显示蓝色「已置顶」，再次点击取消；收起菜单或进出关灯模式时保留置顶状态。关闭投屏窗口即退出程序；重新插线后重新启动，或在右侧刷新设备。

点击右侧「文件与工具」分组中的「快捷键设置」，选择菜单操作，点击输入框并按下快捷键组合，再点击「设置」和「保存」。支持为右侧各个操作及菜单收起 / 展开配置快捷键，也可清除绑定；默认不预设快捷键。组合须包含 ⌘Command、⌃Control 或 ⌥Option，普通文字、无修饰的方向键、粘贴及常用编辑和系统组合保留原用途。重复绑定会提示冲突。配置保存在 `~/Library/Application Support/HarmonyCast/keyboard-shortcuts.properties`（设置 `CAST_STATE_DIR` 时使用该目录），保存后立即生效，重启后仍保留；菜单隐藏时仍可使用，弹窗中不会触发投屏操作，已禁用的操作不会被快捷键执行。

投屏期间手机自动保持常亮，无需修改手机的自动锁屏设置。停止投屏、切换到另一台手机或正常退出 App 时会恢复系统息屏时间；手动按电源键或点击锁屏按钮仍可锁屏。常亮通过每 15 秒续期一次的临时 60 秒息屏时间实现，异常断连或强制结束进程后手机仍可自动息屏（重新连接并正常停止投屏可清除临时覆盖）。

右侧「旋转画面」按钮可把投屏画面旋转 90°（横屏 / 竖屏来回切换），点击坐标会自动跟随画面方向换算；窗口和侧栏的位置保持不变。部分手机系统不支持强制旋转屏幕，此按钮在 App 端直接旋转画面，兼容所有手机。

右侧「关灯模式」按钮隐藏侧栏并全屏暗色显示手机画面，按 ESC 或点击右下角 ☀ 退出，恢复原窗口和右侧操作区。

右侧提供「投屏设置」（分辨率倍率、码率、帧率、I 帧间隔、端口、屏幕 ID，保存后自动重启投屏生效）、「控件树」（查看当前界面控件、点击控件、导入/导出布局 JSON）、「刷新画面」（请求关键帧恢复画面）。右侧提供「设备端横屏 / 竖屏」按钮（部分应用不支持强制旋转）。

右侧提供「解锁」按钮：唤醒屏幕并上滑，检测到数字键盘后弹出隐藏密码输入框，预填本机默认密码。程序读取数字按钮的真实边界逐位点击；鸿蒙隐藏数字文字时，使用锁屏控件树中的标准键盘按钮边界，不再按屏幕比例猜坐标。解锁过程中禁止重复启动，坐标不完整、点击失败或切换设备时停止输入，诊断日志不记录密码。指纹/人脸解锁无法远程模拟。

触摸板双指捏合可直接操作手机：捏合手势通过 Ctrl+滚轮传入，App 会用 uinput 多指触摸向手机发送真实的双指缩放（捏拢 / 张开），在地图、图片、网页等场景可缩放内容；捏合中心跟随鼠标位置。

右侧提供「宏」录制 / 回放按钮：录制时在手机画面上进行的点击、拖动操作会按时间顺序记录下来，回放时用同一触摸注入通道重放，可重复执行固定操作流程（如登录、清缓存、连续翻页）。录制中的操作仍会实时发送到手机。

右侧连接状态实时显示连接方式（Wi-Fi / USB）、画面分辨率、屏幕录制和宏录制 / 回放状态。

投屏画面获得键盘焦点后，Mac 键盘的 ↑ / ↓ / ← / → 分别触发手机上滑 / 下滑 / 左滑 / 右滑，与右侧滑动按钮一致，方向随投屏画面旋转。每次按下执行一次滑动，长按不会堆积重复手势；松开后可再次按下。断连或停止投屏时不发送滑动，弹窗中的方向键保留正常操作。

右侧提供「回桌面 / 最近任务」按钮：回桌面走系统 Home 键通道，最近任务复刻手势导航的「从底部上滑并停留」手势（HarmonyOS 不识别系统任务切换按键），与返回、音量、电源按钮并列，弥补手势导航下没有实体按键的问题。右侧提供「发送文本」按钮：先点击手机上的输入框使其聚焦，再在弹出的对话框里输入文字，App 会把文本直接注入手机的输入框（支持从 Mac 复制的中文等文本）。

右侧提供「粘贴」按钮：一键把 Mac 剪贴板里的文本直接注入手机已聚焦的输入框，发 WiFi 密码、验证码、链接不用手动敲。右侧提供「定时截图」按钮：设置间隔（5–3600 秒）后自动把画面截图保存到桌面，再次点击停止，适合跑测试、盯演示时留记录。

右侧「文字与控件」分组中的「复制画面文字」按钮可把手机上的文字复制到 Mac。打开后先提取当前界面文本，没有可读取文本时自动识别截图；也可在左侧截图上拖动框选，然后点击「识别画面 / 框选区域」读取图片里的文字。右侧结果可编辑，选择「复制选中」或「复制全部」后即可在 Mac 粘贴。清除框选后识别整屏；关闭并重新打开获取最新截图。框选不会操作手机，图片识别在 Mac 本地完成，临时截图会在识别结束后删除；识别结果请检查后使用。

手机画面上按住 ⌥Option（⌥）再点击 = 长按（即使快速点击也会保持按住 650ms），长按桌面图标、列表项、输入框弹菜单都能远程完成；普通按住鼠标不动本身就是长按。右侧提供四个方向快捷滑动按钮（上 / 下 / 左 / 右），一键完成下拉刷新、返回手势、横向翻页等。快捷滑动使用明确的手势起点与终点，方向跟随投屏画面旋转；执行期间切换手机或停止投屏会取消尚未发送的手势。

拖拽文件传输：在设备列表选择手机后，把一个或多个文件直接拖进投屏窗口即可排队发送，传输窗口显示每个文件的状态和批次进度。支持取消未完成的传输；隐藏窗口后继续发送，可从「文件传输」→「拖拽传输记录」重新查看。每批默认保存到手机 `/data/local/tmp/HarmonyCast/` 下的独立目录，窗口可复制完整保存位置；同名文件自动加编号，成功上传后才发布最终文件名。当前调试通道不能访问这台手机的公共下载目录，因此文件保存于调试目录，文件夹暂不支持。传输固定到拖入时选中的手机，切换设备不会改发到新手机。

右侧「截图与录屏」和「文件与工具」分组：截图保存到桌面（`鸿蒙投屏-时间戳.png`）、录屏保存到 `~/Movies/鸿蒙投屏/`（MP4）、窗口置顶切换、文件传输（发送到手机 / 从手机接收，默认路径 `/data/local/tmp/`）。同在右侧的工具按钮：端口转发（把手机端口映射到电脑，如 `localhost:8080` → 手机 80；当前 hdc 版本删除转发可能不生效，重启 App 或拔插设备可清除）、安装应用（选择 `.hap / .hsp / .app` 安装到手机，可覆盖安装）。投屏期间后台检查连接：静止画面不会仅因 8 秒无新帧而重连，连续连接检查失败时等待原手机恢复；采集服务无响应时自动重启投屏，失败重试采用退避；设备列表每 4 秒自动刷新，投屏中切换列表里的另一台手机会自动切换投屏对象。界面按钮不占用键盘焦点，按空格键会直接输入到手机而不是触发按钮。


连接中断后，窗口显示「等待恢复」，原来的 USB 手机或原 Wi-Fi 地址恢复连接后自动尝试投屏；不会自动切换到另一台手机。刷新设备列表保留正在投屏的目标。等待期间仍可点击「停止投屏」取消恢复；手动停止、切换手机后，旧回调和检查结果不能重新启动原会话。画面恢复前暂停鼠标、键盘控制；中断的宏回放需手动重新开始，定时截图在连接恢复后继续。

连接检查使用有超时的 hdc 命令和独立的关键帧 RPC，不向手机注入点击或滑动。每次重连使用独立解码器并释放旧资源。手机 Wi-Fi 地址变化或调试授权被撤销时，仍需按下方无线排查步骤处理。

Mac 键盘输入会按顺序合并连续按键，减少逐键启动远程命令造成的延迟；中文输入、Cmd+V / Ctrl+V 粘贴、退格和回车共享同一输入顺序。停止投屏或切换设备会取消尚未发送的输入。

连接恢复回归测试位于 `tests/`：状态策略、离线记录、指定无线目标、hdc/RPC 超时、多次解码资源释放均有测试；`CaptureLiveTest` 用已连接手机验证静止画面及采集服务中断恢复，`CaptureWindowTest` 用已离线设备编号验证窗口响应和停止。测试程序会正常退出，也会在断言失败时退出，避免 SDK 后台线程残留。

## 无线投屏

已通过 `hdc` TCP 连接 `172.18.32.18:8710` 验证视频流采集、H.264 解码及新版窗口显示。

1. 手机与 Mac 连接同一个可互通的局域网。
2. 双击 `启动无线投屏.command`。无线连接成功后可以拔掉数据线。
3. 首次使用、手机重启或 IP 地址变化后，如果无法连接，请先插线并授权 USB 调试，再重新启动无线入口；它会自动读取手机的 WLAN 地址并重新配置连接。

`wireless-device.txt` 保存最近成功连接的手机地址。启动脚本使用已连接的设备列表，过滤 USB/TCP 切换后残留的离线设备。

`.command` 入口优先使用项目目录中的 Java 17 与 `hdc`，也支持自动发现本机 Java 17 和 `PATH` 中的 `hdc`。App 使用其内置副本。换电脑时按下方「在另一台 Mac 上开发」准备依赖，无需修改源码中的路径。

## 来源与实现

- 上游工具：<https://gitcode.com/OpenHarmonyToolkitsPlaza/HOScrcpy>
- 工具发行版：v1.0.16-beta，SDK：hosScrcpy-1.0.18-beta.jar。
- `AutoStart.java` 自动连接唯一设备；`CastAppearance.java` 为现有投屏和输入组件提供左侧手机画面、右侧分组操作栏和连接状态。
- 窗口可自由缩放，手机画面保持比例；键鼠输入仍使用上游实现。
- `CaptureProbe.java` 是有时限的采集验证程序；启动投屏无需运行它。

画面通过 USB 或局域网 Wi-Fi 传输，不包含云端中转服务。SDK 会向手机调试临时目录部署采集与控制组件。本版为开发调试工具的本机启动封装；未验证声音、受保护内容或其他手机/系统版本。

修改界面源码后，运行以下命令编译，再重新打开启动入口：

```sh
./build.sh
```

## 在另一台 Mac 上开发

仓库保留投屏 SDK、Java 依赖 JAR 和本项目需要的 `vendor/patches/utils/HdcUtil.java`，不需要再克隆上游仓库。完整 JDK、鸿蒙工具链、下载压缩包和生成的 App 不纳入 Git；这些本地依赖也不会因 Git 更新而被覆盖。

1. 克隆仓库：`git clone git@github.com:shidengyun/harmony-mac-cast.git`，进入 `harmony-mac-cast` 目录。
2. 安装 Xcode Command Line Tools：`xcode-select --install`，提供 Swift 编译器和 App 打包工具。
3. 下载与目标 Mac 架构匹配的 **Java 17 JDK**，将解压后的 `Contents/Home/` 放到下面的目录。也可以使用本机已安装的 Java 17，脚本会通过 `JAVA_HOME` 或 macOS 的 Java 查找工具发现它。
4. 下载对应架构的 OpenHarmony SDK，或从本机 DevEco Studio 的 SDK 中复制 `hdc`、`libusb_shared.dylib`、`NOTICE.txt` 到下面的工具目录。确认 `hdc` 有执行权限：`chmod +x vendor/<架构>/toolchains/hdc`。

| 依赖 | Apple Silicon（M 系列） | Intel |
|---|---|---|
| Java 17 JDK | `vendor/arm64/jdk/Contents/Home/` | `vendor/intel/jdk/Contents/Home/` |
| 鸿蒙连接工具 | `vendor/arm64/toolchains/` | `vendor/intel/toolchains/` |
| 可选 Tesseract | `vendor/arm64/ocr/tesseract` | `vendor/intel/ocr/tesseract` |
| 可选 OCR 模型 | `vendor/arm64/ocr/tessdata/` | `vendor/intel/ocr/tessdata/` |

Java 可从 [Azul 的 Java 下载页](https://www.azul.com/downloads/) 选择 Java 17、macOS、JDK 和匹配的 CPU 架构；Intel 版的已验证下载地址见下方。鸿蒙 SDK 下载地址也见下方，请选择匹配架构的工具链。

准备完毕后：

```sh
./build.sh
./启动鸿蒙投屏.command
# 生成本机架构的 App
./package-app.sh
# 在 Apple Silicon 上交叉打包 Intel App（另外准备 Intel 依赖和 Rosetta）
./package-app.sh intel
```

脚本以自身所在的项目目录为基准，可从其他工作目录调用，也支持项目路径包含空格。路径配置变量接受相对路径，例如：

```sh
CAST_BUILD_JDK_PATH=vendor/arm64/jdk/Contents/Home ./build.sh
CAST_RUNTIME_JDK_PATH=vendor/intel/jdk/Contents/Home \
CAST_TOOLCHAINS_PATH=vendor/intel/toolchains ./package-app.sh intel
```

仍支持 `CAST_JAVA_PATH`、`CAST_HDC_PATH`、`CAST_OCR_PATH`、`CAST_TESSERACT_PATH`、`CAST_TESSDATA_PATH` 和 `CAST_STATE_DIR`；相对路径均以项目目录为基准，也可显式指定本机的绝对路径。桌面、影片、App 配置目录由系统用户目录动态确定；手机端的 `/data/local/tmp/` 是设备路径。

图片识别优先使用可用的 Tesseract，未提供对应架构的引擎或系统版本不满足其依赖时使用 macOS Vision。Tesseract 优先从项目依赖目录或 `PATH` 查找，模型目录需要包含 `chi_sim.traineddata`、`chi_tra.traineddata`、`eng.traineddata`。在 `PATH` 中安装 Tesseract 时，打包脚本从其语言列表读取模型目录；交叉打包应提供目标架构的 Tesseract 与模型。

## App 打包

运行 `./package-app.sh` 生成本机架构的 App；也可用 `./package-app.sh arm64` 或 `./package-app.sh intel` 指定目标，分别输出到 `dist/鸿蒙投屏.app` 和 `dist/鸿蒙投屏-Intel.app`。打包脚本编译界面、通过 `jlink` 制作对应架构的运行环境、复制匹配的 FFmpeg 和鸿蒙连接工具、生成图标与原生启动器，并执行本地 ad-hoc 签名。两个 App 使用独立的 Bundle ID，避免 macOS 将它们识别为同一个安装实例。每次成功打包都会将对应 App 的完整副本同步到 `~/Desktop/`；原有输出和桌面旧版本（或快捷方式）备份到 `dist/backups/`。仅需重新同步已有产物时，可运行 `bash scripts/sync-desktop-app.sh arm64` 或 `bash scripts/sync-desktop-app.sh intel`。

两个版本的启动器均以 macOS 13 为最低版本编译。Apple Silicon 版本已在本机验证；Intel 版本已通过 Rosetta 验证 x86_64 启动器、Java、USB 和 Wi-Fi 两种模式的实际投屏，均收到 1276 × 2848 的手机画面。Intel 真机上的运行情况仍需确认。当前签名用于本机运行，尚未经过 Developer ID 签名或 Apple 公证。

Apple Silicon 和 Intel 两个 App 都内置 Tesseract、本地依赖及简体中文、繁体中文、英文模型，无需额外安装 OCR 工具。Apple Silicon 版已在本机验证界面文本提取、框选识别、剪贴板复制及真实手机截图识别。Intel 版内置官方 Homebrew Ventura 的 Tesseract 5.5.1 和 16 个 x86_64 二进制文件，已通过 Rosetta 验证英文、简体中文、繁体中文图片识别与临时路径读取；尚未在 Intel 真机验证。`.command` 入口优先使用本机或项目依赖目录中的 Tesseract，否则尝试系统 Vision。

Apple Silicon 版内置 Tesseract 依赖要求 macOS 26.4 或更新版本，Intel 版要求 macOS 13.0 或更新版本；系统版本不满足 OCR 依赖时自动使用 Vision，该回退尚未在旧系统实测。App 的投屏功能保持 macOS 13 最低版本。

Intel 版使用 Azul Zulu OpenJDK 17.0.21.0.3 x86_64、OpenHarmony 6.1 Release 的 hdc 3.2.0c 与 `macosx-x86_64` FFmpeg 解码库。Java 下载包已核对官方 SHA-256：`6de9a31bd21c09b787781ce90d5791168b522c2213571d742141e610b81ff7fd`。

重新准备 Intel OCR 依赖时，可运行：

```bash
python3 scripts/setup-intel-ocr.py --tessdata-dir /path/to/tessdata --proxy http://127.0.0.1:7890
```

模型目录需包含 `chi_sim.traineddata`、`chi_tra.traineddata` 和 `eng.traineddata`；不需要代理时省略 `--proxy`。脚本从 Homebrew 官方镜像下载固定版本的 Intel 包，校验 SHA-256，按实际动态库引用补齐依赖并改成可移动的加载路径。文件保存在 `vendor/intel/ocr-prefix/`，下载来源与校验值记录于其中的 `intel-ocr-manifest.json`；`vendor/intel/ocr/` 提供打包入口和模型。此后 `./package-app.sh intel` 会自动内置这些资源。可用 `bash tests/intel-ocr-test.sh` 验证最终 Intel App。

Intel 构建依赖：

- Java：<https://cdn.azul.com/zulu/bin/zulu17.70.113-ca-jdk17.0.21.0.3-macosx_x64.tar.gz>，解压到 `vendor/intel/jdk/`，内部保留 `Contents/Home/` 结构。
- 连接工具：<https://repo.huaweicloud.com/openharmony/os/6.1-Release/ohos-sdk-mac-public.tar.gz>，取其中 `toolchains-darwin-x64-6.1.0.31-Release.zip` 的 `hdc`、`libusb_shared.dylib` 和 `NOTICE.txt`，放到 `vendor/intel/toolchains/`。
- 构建脚本也支持用 `CAST_RUNTIME_JDK_PATH` 和 `CAST_TOOLCHAINS_PATH` 指定现成的对应架构依赖。Apple Silicon 主机执行 Intel 的 `jlink` 需要 Rosetta。

启动时的连接命令由 `HdcCommand.java` 设置超时，避免失效的无线地址令 App 一直等待。新测试手机可以通过 USB 授权后在设备下拉框中选择；无线模式优先使用上次记住的地址。

## 无线投屏失败排查（手机无法被当前 WiFi 发现）

无线投屏通过「IP 直连」发现手机：Mac 直接连接手机的 WiFi 地址（`hdc tconn <IP>:8710`），不是广播式自动发现。因此手机必须与 Mac 在同一局域网，且地址是手机**当前**的 WLAN 地址。常见失败原因：

- **记忆的地址已过期**：`wireless-device.txt` 里保存的是上次成功连接的网络（如 `172.18.32.x`），手机换 WiFi、重启或路由器重新分配地址后，该地址不再有效。程序会尝试记忆的地址；连接失败时可插线，让设备列表自动读取手机当前 WLAN 地址。IP 地址的前三段不同也可能处于同一局域网，因此不再仅按地址前缀跳过连接。
- **手机与 Mac 不在同一网络**：手机连了别的 WiFi / 热点，或 Mac 走有线而手机走另一个路由器的 WiFi。请把手机连到与 Mac 相同的 WiFi。
- **路由器开启「AP 隔离 / 访客网络」**：同一 WiFi 下设备之间互相不可达，`ping` 手机地址不通。
- **手机 WiFi 未开启或未连接**：无法读取到 WLAN 地址。

处理步骤：

1. 双击 `诊断无线投屏.command`，查看 Mac 网段、记忆目标、可达性和手机 WLAN 地址，确认两台设备网段一致。
2. 手机连接与 Mac 相同的 WiFi，用 USB 数据线连接并授权「USB 调试」。
3. 重新运行 `启动无线投屏.command` 或 App；工具会自动读取手机当前 WiFi 地址并保存，成功后即可拔线。
4. 仍失败时检查路由器「AP 隔离 / 访客网络」设置，或在 macOS 系统设置里临时关闭防火墙再试。
